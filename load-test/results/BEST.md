# 위험 서비스 검증·측정 상태

## 정확성 기준

- 마지막 남은 한도에 대한 20개 동시 요청 중 한 건만 예약됩니다.
- 같은 betId와 요청 fingerprint로 100회 요청해도 예약은 한 건입니다.
- 다른 fingerprint는 충돌하고 해제·만료·확정 뒤 합계가 일치합니다.
- `bet.placed.v1` 재전달은 확정 집계와 패턴 이력을 중복 반영하지 않습니다.

이 항목은 원자성과 멱등성 검증이며 처리량 측정이 아닙니다.

## 성능 상태

reservation API, 진단 API와 Kafka 소비 경로에 대해 채택한 RPS나 p95/p99는 아직 없습니다. `consumer_throughput.sh`의 합성 바이트 발행 시간은 유효한 Avro 소비와 최종 Redis 반영을 측정하지 않으므로 consumer 처리량으로 사용하지 않습니다.

성능 결과를 추가할 때에는 초기화된 Redis·Kafka, 자원 제한, Java와 Redis 버전, 요청 분포를 기록하고 응답 성공뿐 아니라 최종 예약·카운터·이력 개수까지 확인해야 합니다. 카운터 키는 통화를 포함하지 않으므로 KRW 이외 결과는 키 이행 전까지 채택하지 않습니다.
